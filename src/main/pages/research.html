The Research Behind the Book

Java by Comparison grew out of a teaching concept for clean code that we developed, applied, and evaluated at the University of Bamberg for more than six years.

Teaching Clean Code, Not Just Working Code

Programming courses at university usually grade functional correctness. Code that works but is hard to read and maintain passes, although the software industry needs developers who write clean code. Our courses put clean, maintainable code first.

The concept, which received the faculty's teaching award, works like this:

  1. Group assignments. Students in their second and third year solve four programming assignments per semester in teams.
  2. Detailed textual code review. Every submission gets a review that explains what is wrong with the code, how to write it better, and why the better version is really better.
  3. A knowledge base of before/after comparisons. Over the years, we noticed that we told every new generation of students the same things. We collected the typical issues of Java learners as comparisons of flawed and improved code. A reviewer only needs to reference the matching comparison, which makes feedback faster and better: students see the problem and the rationale behind the solution.
  4. Curated static analysis checks. A selected set of static code analysis rules helps reviewers spot violations quickly.

That knowledge base became the book. Its 70 items are based on code we faced when correcting our students' programming assignments.

Publications

Teaching Clean Code

Linus W. Dietz, Johannes Manner, Simon Harrer, Jörg Lenhard. 1st Workshop on Innovative Software Engineering Education (ISEE 2018), co-located with SE 2018, Ulm, Germany. CEUR Workshop Proceedings, Vol. 2066, pp. 24–27, 2018.

Presents the feedback-driven teaching concept for clean code and evaluates one semester of student submissions (n=18) with static code analysis tools, which shows steady progress. It identifies the correction of assignments as the bottleneck for scaling the course and proposes the knowledge base of before/after comparisons, plus curated static analysis checks, to shorten the time to feedback.

Code Process Metrics in University Programming Education

Linus W. Dietz, Robin Lichtenthäler, Adam Tornhill, Simon Harrer. 2nd Workshop on Innovative Software Engineering Education (ISEE 2019), co-located with SE 2019, Stuttgart, Germany. CEUR Workshop Proceedings, Vol. 2308, pp. 23–26, 2019.

Mines the Git repositories of 38 student teams in two Bamberg courses, Advanced Java Programming and Introduction to Parallel and Distributed Programming, which use Java by Comparison to point students to issues in code reviews. It analyzes how eight code process metrics relate to students' scores and finds only weak correlations.

From the Classroom to Industry: The Kata

We turned the method into a two-hour team exercise. Pairs clean up deliberately uglified legacy code and may only apply comparisons from the book. At the first run, at the BMW Group coding dojo on March 25, 2019:

  • 19participants
  • 39 / 70comparisons used
  • 120minutes

The teams favored the chapters Name Things Right and Start Cleaning Up. The most used comparisons were Avoid Abbreviations and Avoid Negations: quick fixes with a large effect on readability. Run the kata with your team.

Teaching with the Book

  • In code reviews and grading. Point students to the matching item instead of writing the same explanation again. Each item shows the problem and the solution side by side.
  • Alongside any programming course. Once students know basic Java syntax, the book can accompany basically any course with programming tasks. A FizzBuzz exercise is a good readiness check.
  • For coaching junior developers. Senior developers use it the same way in industry.
  • With the free material. The preface and three items are free samples, and the kata with code and tests is on GitHub.
